# Выпуск KinoStream

## Локальная сборка

Требуются Xcode, macOS и публичная конфигурация Supabase в `.env`. Файл должен содержать только `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY`. Скрипт отклоняет секретные ключи и дополнительные переменные, не печатая значения.

```sh
bash scripts/package-release.sh
```

Результат находится в `dist/v<версия>/`: приложение, DMG, ZIP и описание. В приложение включается публичная конфигурация Supabase, поэтому получателям не нужно заполнять `.env`. Личный TorrServer, ключ Кинопоиска и данные локального аккаунта в пакет не входят.

Текущий скрипт создаёт локальные ad hoc подписи приложения и TorrServer. Это не подпись Developer ID и не нотариальное заверение Apple. Публикуйте такую сборку только с соответствующей пометкой в описании.

Для повторной сборки перенесите старую папку `dist/v<версия>/KinoStream.app` либо увеличьте версию. Скрипт не удаляет предыдущие сборки автоматически.

## Релиз GitHub

1. Проверьте состав исходников и исключение `.env`, сборок, пользовательских настроек Xcode и временных данных Supabase.
2. Зафиксируйте исходники и создайте тег версии.
3. Приложите DMG, ZIP, `SHA256SUMS.txt`, официальный архив исходников TorrServer соответствующей версии и `TORRSERVER-SOURCE.md`.
4. Используйте описание из `docs/releases/`. Укажите требования macOS/архитектуры и статус подписи.

Не публикуйте файл `.env` отдельно. В готовом приложении допускаются только публичные параметры Supabase, проверенные скриптом; безопасность пользовательских строк обеспечивается RLS в Supabase.

## Следующий выпуск

Обновите `CFBundleShortVersionString` в `KinoStream/Info.plist` и `CFBundleVersion` для новой сборки, создайте соответствующее описание в `docs/releases/`. Для обычного распространения подготовьте Developer ID signing, подпишите вложенный TorrServer, выполните нотариальное заверение и прикрепите билет Apple к образу.
