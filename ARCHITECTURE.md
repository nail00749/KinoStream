# Архитектура KinoStream

## Продуктовый поток

KinoStream — нативное приложение macOS на SwiftUI. Каталог объединяет поиск и метаданные Cinemeta с русскоязычными данными Kinopoisk API. JacRed ищет раздачи, а TorrServer добавляет и отдаёт выбранное видео. Приложение включает arm64-бинарник TorrServer и может запускать его как локальный дочерний процесс; также доступен режим подключения к внешнему серверу.

Cinemeta и Кинопоиск → карточка и сезоны/серии → JacRed → TorrServer → встроенный плеер или VLC

Приложение не устанавливает и не запускает JacRed. Режим TorrServer по умолчанию — встроенный; пользователь может переключиться на внешний и указать его адрес и Basic Auth. HTTP-интерфейс встроенного процесса слушает только loopback (`127.0.0.1`); Bonjour, DLNA, LPD и UPnP отключены. Торрент-движок сохраняет обычный доступ к интернет-пирам. Данные хранятся в `~/Library/Application Support/KinoStream/TorrServer`, процесс останавливается при завершении приложения. Target собирается только для Apple Silicon (`arm64`).

## Слои и ответственность

- App: навигация и фасад состояния AppModel.
- Core/Catalog: клиенты Cinemeta и Kinopoisk, объединение и преобразование результатов в модели приложения.
- Core/Domain: модели фильма, серии, раздачи и поискового запроса.
- Core/Persistence: секреты в Keychain, отметки, кэш метаданных, локальные библиотеки аккаунтов и версии облачных записей.
- Core/Search: клиент JSON API JacRed.
- Core/TorrServer: проверка, добавление/удаление, файлы и воспроизведение.
- TorrServerProcessController: запуск, состояние и остановка локального arm64-процесса.
- PlaybackController: фиксация контекста до сетевого запроса, точный выбор файла по координатам серии, история ручных раздач и запуск из сохранённых источников.
- Features: нативные SwiftUI-экраны главной страницы, каталога, поиска, коллекции, плеера и настроек.

- CinemetaClient ищет фильмы и сериалы в публичном каталоге Stremio и получает подробные карточки по IMDb ID. Пользовательский API-ключ не нужен.
- KinopoiskClient дополняет каталог русскими названиями, описаниями, рейтингами, постерами и сезонами/сериями. Поиск идёт через API v2.1, карточки и эпизоды — через API v2.2. Запросы используют заголовок X-API-KEY.
- MediaCatalogClient запрашивает оба источника параллельно, объединяет совпадения по IMDb ID либо названию и году, а при сбое одного оставляет результаты второго. Запрос короче двух символов не отправляется.
- JacRedClient передаёт поисковую фразу, название, оригинальное название, год и тип контента в JSON API. Для эпизода поисковая фраза включает SxxEyy. Пользовательский API-ключ публичному сервису не нужен.
- TorrServerProcessController находит свободный локальный порт, подготавливает настройки без LAN-обнаружения и запускает bundled binary на `127.0.0.1`; данные сервера хранятся в Application Support.
- TorrServerClient не ищет торренты. Он подключается к активному локальному или внешнему серверу, принимает выбранный magnet или URL, показывает раздачи и файлы, а также формирует URL для воспроизведения. Плеер выбирается в настройках: встроенный AVKit или установленный VLC.
- CatalogStore хранит избранные фильмы и сериалы, избранные раздачи, просмотренное, позиции воспроизведения и локальный кэш метаданных. Отдельная локальная привязка серии или фильма к хешу раздачи и ID файла позволяет запустить их из «Просмотренного» через «Мою коллекцию»; исходные magnet/torrent-ссылки в этой привязке не хранятся. Если раздачи больше нет в TorrServer, KinoStream открывает поиск нужного фильма или эпизода. Привязка остаётся на устройстве и не синхронизируется через Supabase. Экран «Избранное» объединяет фильмы/сериалы и раздачи в отдельных вкладках; сердца в каталоге и поиске добавляют объект в соответствующую вкладку. Просмотренное показывает для каждой сохранённой позиции таймкод, прогресс и время последнего просмотра, включая эпизоды сериалов. Карточки используют IMDb ID и, когда он известен, Kinopoisk ID. Старые IMDb- и TMDB-записи поддерживаются для сохранения локальной коллекции.
- Supabase отвечает за email/password-аккаунт и синхронизацию библиотеки между устройствами. В облако отправляются избранные фильмы и сериалы, отметки просмотра, прогресс и метаданные нужных карточек. Избранные раздачи и их magnet/torrent-ссылки, адрес и пароль TorrServer, а также ключ Кинопоиска остаются локальными, чтобы не передавать потенциально приватные ссылки.
- Сессия Supabase хранится в macOS Keychain. URL проекта и публичный anon/publishable key берутся из локального `.env`, который исключён из Git и добавляется в ресурс приложения при сборке. `service_role` ключ не используется в клиентском приложении.
- До открытия основного интерфейса пользователь входит или создаёт аккаунт. Если `.env` не заполнен, приложение показывает инструкцию по настройке.
- Старая таблица `kinostream_library` сохранена для первого импорта. Новая таблица `kinostream_library_entries` хранит отдельные записи избранного, отметок просмотра, прогресса и метаданных. Обе таблицы защищены RLS по `auth.uid()`. Новая миграция: `supabase/migrations/20261001000000_kinostream_library_entries.sql`.
- RPC `merge_kinostream_library_entries` атомарно сравнивает версию каждой записи: время изменения и идентификатор операции. Независимые изменения разных записей сохраняются; для одной записи действует last-write-wins. Удаления сохраняются как tombstone-записи, чтобы старое устройство не восстановило удалённые данные. Время берётся с устройства, поэтому точность часов влияет на конфликтующие правки одной записи. Данные загружаются страницами, чтобы не упереться в лимит строк PostgREST. Старый снимок импортируется только в пустую таблицу новых записей аккаунта. Все устройства нужно обновить: старые сборки используют прежнюю таблицу.
- Перед показом нового аккаунта CatalogStore переключает локальную библиотеку. Библиотека предыдущего пользователя архивируется локально вместе с источниками и избранными раздачами; при возвращении аккаунта восстанавливается его кэш. Ошибка сети не показывает историю другого пользователя. События плееров проверяют аккаунт; текущая синхронизация не отменяется каждой новой записью прогресса. Другие устройства подтягивают изменения при запуске, активации окна или вручную. При временной ошибке выполняется до трёх повторов.
- Главная показывает продолжение последнего просмотра каждого фильма/сериала и следующую известную серию после завершённой. Встроенный плеер предлагает кнопку «Следующая серия» после достижения порога завершения; при отсутствии локального источника открывается поиск нужного эпизода. Для локальных раздач без полного каталога следующая серия не угадывается. Полный список эпизодов отмечается после успешной загрузки у провайдера; синтетическая карточка одной серии не означает завершение всего сериала. Повторный поиск сохраняет загруженные сезоны в кэше.
- Встроенный плеер периодически сохраняет время; при повторном запуске видео продолжается с сохранённой позиции. После 90% просмотра фильм или серия автоматически помечаются просмотренными. Для VLC приложение при запуске отслеживаемого видео включает HTTP-интерфейс на случайном loopback-порту `127.0.0.1` с временным паролем, раз в секунду получает только позицию, длительность и состояние и сохраняет прогресс через CatalogStore. При повторном запуске позиция передаётся VLC как время старта. Magnet-ссылки и ответы статуса не сохраняются и не журналируются.
- SwiftUI-представления отображают состояние и отправляют действия в AppModel и модели хранения; HTTP и разбор сетевых DTO вынесены из представлений.

Ключ Kinopoisk API и пароль TorrServer хранятся в macOS Keychain. Адреса сервисов и локальная история хранятся в UserDefaults. Не записывать API-ключи, пароли или magnet-ссылки в логи.

## Технологии

- SwiftUI и один нативный macOS target; текущая минимальная версия — macOS 14.
- URLSession и async/await для сетевых запросов.
- JSONSerialization для ответа JacRed без сторонних зависимостей.
- Keychain для секрета TorrServer и ключа Kinopoisk API; UserDefaults для адресов и локальной истории.
- Supabase Swift SDK для email/password-авторизации и синхронизации через PostgREST; сессия хранится в KeychainLocalStorage.
- AVKit для встроенного воспроизведения, NSWorkspace для запуска VLC с отдельным локальным HTTP-интерфейсом и URLSession для чтения его статуса.

## Настройка

1. По умолчанию запускается встроенный TorrServer. Для внешнего сервера выбрать режим «Внешний», указать адрес и при необходимости Basic Auth.
2. При желании ввести ключ Kinopoisk API. Он хранится в Связке ключей macOS; без него поиск продолжает работать через Cinemeta.
3. При необходимости изменить адрес JacRed.
4. Проверить соединения с Cinemeta, Кинопоиском, JacRed и TorrServer кнопками в настройках.
5. Для синхронизации применить SQL-файл из `supabase/migrations`, скопировать `.env.example` в `.env`, заполнить `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY`, затем пересобрать приложение и войти или создать аккаунт. Использовать только публичный anon/publishable key, не `service_role`.

Kinopoisk API требует зарегистрированный ключ и имеет квоты и ограничение частоты запросов. Cinemeta доступен как публичное Stremio add-on API; доступность зависит от внешнего сервиса и интернет-соединения.

В приложение включён официальный TorrServer `MatriX.145` для Darwin arm64. Его лицензия GPL-3.0 включена в ресурсы приложения. Перед распространением KinoStream необходимо соблюдать условия GPL для этого компонента и предоставить соответствующий исходный код TorrServer.

JacRed может возвращать magnet или URL загрузки torrent-файла. Ссылка должна быть доступна с машины, где работает TorrServer, поэтому в первую очередь используется magnet.

## Раздачи и автоматическое продолжение

- TorrentSearchFilters фильтрует уже полученные результаты JacRed по разрешению, максимальному размеру в байтах, минимальным сидам, языку и озвучке. Есть сортировка по сидам и размеру. Язык, озвучка и разрешение определяются только по явным маркерам названия; неизвестные значения не проходят соответствующий фильтр. Размер из JSON сохраняется отдельно от локализованной подписи; старые избранные раздачи декодируются без sizeBytes.
- В «Моей коллекции» кнопка привязки открывает поиск карточки Cinemeta/Кинопоиск. После выбора загружаются подробности, для серии без номера сезона задаётся сезон, а для фильма с несколькими видео выбирается основной файл. Номера SxxEyy в файлах имеют приоритет. Появляются постер и название карточки; локальный прогресс переносится к каноническим идентификаторам, уже существующие записи выбираются по времени последнего просмотра. История других канонических карточек остаётся отдельной. Сохраняются локальные источники для открытия серий, в облако отправляются только метаданные и прогресс.
- PlaybackController ведёт общий отменяемый отсчёт 10 секунд после конца эпизода. Встроенный плеер использует уведомление AVPlayerItemDidPlayToEndTime, VLC — переход playing → stopped после достижения последних двух секунд. Ручная остановка VLC у самого конца может считаться завершением; недоступный HTTP-статус не запускает переход. Для VLC отсчёт показывается в окне KinoStream и приложение активируется. Известная следующая серия открывается общим маршрутом: локальный файл, выбор файла либо поиск нужной серии. Без полного списка эпизодов автопереход не запускается. Его можно отключить в настройках; смена аккаунта, закрытие встроенного плеера и начало нового видео отменяют отсчёт.

## Подготовка видео, раздача сезона и подборки

- PlaybackLoadingState и PlaybackController показывают этапы подключения, добавления, получения файлов, ожидания пиров, открытия плеера и буферизации. Ожидание пиров определяется по activePeers, скорость и число пиров берутся из текущего списка TorrServer. AVPlayer наблюдается через status и timeControlStatus, VLC подтверждает запуск через HTTP-статус. При ошибке доступны повтор последней попытки и поиск альтернативы для текущего фильма/эпизода. Буферизация или открытие дольше 45 секунд дают сообщение с действиями. Отмена прерывает задачу подготовки; уже добавленная раздача остаётся на сервере. Поздние ответы проверяют идентификатор попытки и аккаунт.
- CatalogStore сохраняет локальный preferredSeriesSources по карточке и сезону. Выбранная раздача применяется к следующим сериям этого сезона; сохранённый конкретный файл используется только из той же раздачи. Неразмеченный одиночный файл не подставляется вместо следующей серии. При отсутствии раздачи или однозначно подходящего файла показывается предложение выбрать замену. Сменить раздачу также можно в карточке сериала. Выбор архивируется вместе с локальной библиотекой аккаунта; в Supabase не отправляется. Для прежних библиотек начальный выбор выводится из последнего локального просмотра сезона.
- CatalogDiscoverySelection задаёт популярное, новинки текущего года, высокий рейтинг, жанр и вид контента. Cinemeta использует каталоги top, year и imdbRating, объявленные в [манифесте провайдера](https://v3-cinemeta.strem.io/manifest.json). Новинки ограничены текущим годом; жанр для них применяется к полученной странице, поскольку параметр genre в каталоге year означает год. Это не полный каталог всех релизов. При сбое одного вида контента остаются доступные карточки второго; устаревшие подборки после ошибки не показываются под новым заголовком. Поиск и подробности продолжают объединять Cinemeta и Kinopoisk.

## Дальнейшие решения

- Добавлять новые источники каталога через отдельные клиенты и сведение к модели MediaItem.
- Рассматривать локальный прокси для прямых URL только после проверки, что TorrServer не может скачать выбранную ссылку напрямую.
- Выносить код в отдельные Swift Packages только при появлении устойчивых границ или независимой переиспользуемости.
