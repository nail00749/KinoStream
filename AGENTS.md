# Инструкции для агентов

## Цель проекта

KinoStream — нативное приложение для macOS на SwiftUI. Приложение подключается к TorrServer, помогает находить и добавлять раздачи и воспроизводит выбранные видео. Поддерживаются встроенный локальный arm64 sidecar и внешний сервер.

## Общие правила

- Сначала прочитай этот файл и `ARCHITECTURE.md`, затем изучи существующие реализации и соглашения проекта.
- Следуй выбранным пользователем решениям. Если решение ещё не принято, используй рекомендации из `ARCHITECTURE.md` как временный вариант и отмечай это в итоговом сообщении.
- Используй согласованный поток Cinemeta + Kinopoisk API → JacRed → TorrServer: Cinemeta и Kinopoisk отвечают за карточки, метаданные и сезоны/серии, JacRed — за поиск раздач, TorrServer — за добавление и воспроизведение. Не возвращай поиск в TorrServer/RuTor без решения пользователя.
- Поддерживай два режима TorrServer: встроенный локальный arm64 sidecar (решение пользователя одобрено) и внешний сервер с пользовательским адресом. HTTP-интерфейс встроенного процесса слушает только `127.0.0.1`; отключены Bonjour, DLNA, LPD и UPnP. Данные хранятся в Application Support, сборка доступна только для Apple Silicon. Не скачивай и не обновляй сервер автоматически.
- Сохраняй нативный macOS-интерфейс на SwiftUI. Не добавляй WebView или кроссплатформенный UI без прямой причины и согласования.
- Не меняй публичные API TorrServer, модели или общие маршруты без проверки всех использований. Учитывай, что ссылки на загрузку, которые выдаёт JacRed, могут быть доступны только с машины самого приложения; предпочитай magnet, если он есть.
- Представления отвечают за отображение и пользовательские события; сетевые запросы, хранение и правила предметной области держи вне SwiftUI View.
- Используй `async/await` для ввода-вывода. Передавай в UI понятные ошибки; не показывай сырые ответы сервера и не пиши пароли, magnet-ссылки или другие пользовательские данные в логи.
- Секреты храни в Keychain. Ключ Kinopoisk API хранится локально под отдельной учётной записью. Не добавляй реальные пароли, ключи провайдеров или адреса личных серверов в исходники и примеры.
- Для облачной синхронизации используй Supabase только для избранного, просмотренного, прогресса и нужных карточек метаданных. Не синхронизируй сохранённые magnet/torrent-ссылки, настройки или секреты сервисов. В клиенте допустим только публичный anon/publishable key; `service_role` запрещён. Защищай строки RLS-политиками по `auth.uid()`.
- Не добавляй зависимости, сервисы, телеметрию и функции, не нужные для согласованного сценария.
- Не запускай тесты и не добавляй новые тесты без просьбы пользователя. Если проверку сборки выполнить нельзя, точно сообщи причину.
- Не делай коммит, публикацию или отправку данных во внешние сервисы без явного поручения.

## Работа нескольких агентов

- Координирующий агент владеет продуктовыми решениями, общими моделями, навигацией и контрактами между слоями.
- Делегируй только ограниченные независимые задачи. Перед делегированием зафиксируй затрагиваемые файлы и интерфейсы.
- Не назначай двум агентам одновременную правку одного файла, `project.pbxproj`, общих моделей или навигации.
- Для работы параллельно разделяй задачи по независимым функциям: например, экран настроек и отдельная интеграция каталога.
- Каждый агент в завершении указывает изменённые файлы, выполненные проверки и оставшиеся ограничения.
- Перед объединением проверь изменения на согласованность с архитектурой и другими уже внесёнными правками.

## Стиль Swift

- Имена типов и методов — на английском, пользовательские строки приложения — на русском, если пользователь не выбрал другой язык.
- Предпочитай небольшие типы и файлы с одной ясной ответственностью.
- Модели для UI не должны зависеть от JSON-формата TorrServer.
- Не создавай одноразовую абстракцию без второго сценария или явного требования к подмене реализации.
